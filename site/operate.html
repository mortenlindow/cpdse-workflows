Operating the services

The internal manual for running CPDSE engagements. A human-in-the-loop pipeline: four prompt steps, two workshops, ~7–8 hours of consultant time per group.

Today only the Research & DS Strategy workflow is fully built. The Educational workflows (Course Upgrade, Staff Upskilling, New Course Creation) and Internal self-improvement are stubs — see services/README.md.

The pipeline at a glance

Passive collection (lab site, grants, pubs, READMEs) (1h)
  → Active intake: questionnaire async + Meeting 1 interview (1h)
  → Step 1 → Step 2 → Step 3 → Step 4
  → QA (1h) → Workshop 1 (2h) → Workshop 2 (1.5h) Total consultant time: ~7–8h

How to run each step

Recommended setup: clone the repo locally and run Claude Code from the project root. Steps 1 & 2 can also be run in claude.ai with file attachments — useful when you need a long context window for messy passive material. Save every output as a file in engagements/ENG###-{LastName}/ before moving to the next step.

Inputs: passive vs active

The engagement starts with both. Pull the passive material before Meeting 1 so you can ask sharper questions; treat the active inputs as the source of truth where they conflict with the passive ones.

Passive
  • Lab website / group page
  • Recent grant abstracts
  • Last ~3 years of publications
  • GitHub READMEs & pinned repos
  • Group's own internal docs if shared
Active
  • Intake questionnaire (PI fills async)
  • Meeting 1: walkthrough + corrections
  • Self-rating L1–L5 across the 7 PDS domains
  • Team roster with named bandwidth
Before you start: create the engagement folder and drop all source material in.

Recommendation Synthesis

Recommend · capacity-calibrated
Prompt

Inputs
Steps 1 + 2 + 3 outputs.
Output
outputs/step4-recommendations.md — quick wins (4 wks) / strategic (3–6 mo) / horizon (18–24 mo) + Competency Model Note.

In Claude Code:

> Run step 4 for ENG042-Hansen. Prompt: services/01-research-strategy/prompts/04-recommendation-synthesis.md Inputs: outputs/step1, step2, step3 Output: outputs/step4-recommendations.md Hard rule: every recommendation gets a named owner from the actual team (see Step 1 team roster) and a person-days/weeks estimate. Design principles

  • Step 1 is factual-only. Gap judgements live in Step 3, never earlier.
  • Structural vs technical is the analytical frame, not a label. It shifts the conversation off "tools to learn."
  • [BEYOND REFERENCE] and [OUTSIDE MODEL] flags are first-class outputs — they improve the model, not error states.
  • "A recommendation that exceeds capacity is a wish, not a recommendation."
  • The brief is handed over at the end of Workshop 1, not before. Workshop 1 produces shared ownership of the diagnosis; the brief is a record, not a script.

Workshop 1 facilitation

Two hours, six blocks. Designed around Know / Feel / Do and grounded in the 4Cs of Training from the Back of the Room (Bowman): Connections, Concepts, Concrete Practice, Conclusions. See the pedagogic model.
